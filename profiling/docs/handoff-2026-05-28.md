## How three-regime works (no fits)

### Step 1 — Classify the cell

Per-turn `pressure[t] = scheduled_requests[t] × per_session_blocks(turn) / available_kv_blocks`.

| regime | rule | example |
|---|---|---|
| **FLAT** | `max(pressure) < 1` — cohort fits in KV throughout | chat c≤200, agentic c≤20 |
| **PERTURBING** | peak ≥ 1 but `late_pressure < SATURATION_FLOOR=1.2`, OR cumulative cohort completion (`scheduled_requests` dropped > 30%) AND `late_pressure < 1.2` | chat c=256/320; osworld c=80–160 |
| **SATURATING** | sustained `late_pressure ≥ 1.2` (no recovery) | swe c≥40; terminal c≥80; osworld c≥200 |

Three constants (`K_SUSTAIN=2`, `BURST_COMPLETION_FRACTION=0.30`, `SATURATION_FLOOR=1.2`) — each derives from a stated physical rule about KV pool behavior; none are tuned by minimizing MAPE.

### Step 2 — Pick a per-turn shape

**FLAT** → `pred[t] = T_min[t]` (closed-form roofline directly).

**SATURATING** → 3-turn sharp ramp from `T_min[t]` to per-turn `T_max[t]`
where `T_max[t] = T_lower + clamp(pressure−1, 0, 1) × (T_upper − T_lower)`.
At pressure ≈ 1.4 (osworld c=200, moderate saturation) → ~90 ms ceiling. At
pressure ≥ 2 (swe c=80) → physical T_upper ≈ 205 ms. The ramp width is
3 turns physically motivated by vLLM's admission-cycle settling time.

**PERTURBING** → smooth per-turn blend weighted by pressure overshoot, with
`T_max[t] = cached_prefill_step_ms(U, P) + scheduler_overhead` divided by
observed `coverage` (= `engine_total_decode_slots / (engine_steps × engine_max_decode_batch)`).
Caps at the llm-d per-cell mean.

## Reporting conventions (be consistent)

- **MAPE** = mean of |pred − obs| / obs. **This is what the dashboard
  displays.** Sensitive to outliers (turn-0 cells can hit 800% APE).
- **median APE** = 50th percentile. Tail-robust view.
- The validator's verdict markdown reports both, side-by-side.

Use MAPE when comparing to the dashboard or talking about overall accuracy.
Use median APE when discussing per-turn shape match without outlier noise.

## Open paths forward

1. **swe/terminal late-turn under-prediction** (predicted ~200ms vs observed
   ~250ms). Pressure-scaling caps at physical T_upper = 205. The remaining
   gap is per-session ITL burstiness that requires modeling vLLM's
   scheduler fairness — likely needs a per-step cohort simulator using the
   kernel lookup. Significant effort; defer until next major model bump.

2. **Workload-only coverage prediction.** Today coverage uses observed
   `engine_total_decode_slots` (telemetry). Predicting coverage from
   workload + chunk size alone would make three-regime fully pure-forward.
   Likely formula: `coverage ≈ max(0, 1 − pending_prefill_per_step / chunk)`.

3. **Turn-0 MAPE outliers** (up to 240%). Bench excludes initial prefill
   from TPOT (in TTFT) but our model amortizes prefill_demand into TPOT.
   Fix: when turn_index = 0, set `prefill_demand` contribution to T_max = 0.

4. **Hardware/model generalization.** All anchors (`util_flops=0.65`,
   `util_bw=0.93`, `scheduler_overhead=5.7ms`, `available_kv_blocks=27250`)
   are H100 + Llama-3.1-8B + vLLM v1. Re-derive when changing any of those.
