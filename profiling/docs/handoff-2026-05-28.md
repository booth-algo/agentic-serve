# Session handoff — 2026-05-28

## Headline

A new TPOT predictor — **two-roofline + turn-history** — has been added
alongside the existing closed-form roofline and llm-d augmenter. It wins
2.4–2.5× over the prior best on swe/terminal at high c, holds parity on
chat/osworld, and uses **no fitted constants** — every input comes from
`RooflineParams`, the empirically-confirmed `max_num_batched_tokens=8192`,
or per-turn engine telemetry.

## What landed

1. **Two-roofline predictor** in [simulator/two_roofline_tpot.py](/root/agentic-serve/simulator/two_roofline_tpot.py).
   Each turn's TPOT is a smooth interpolation between:
   - `T_lower` — decode-bw roofline: `(weights + running × ctx_mid × kv_bytes) / (bw·util_bw)`
   - `T_upper` — chunked-prefill saturation: `max_num_batched_tokens × prefill_per_token ≈ 205 ms`

   The interpolation weight is `w = clamp((pressure − 1) / 2, 0, 1)` where
   `pressure = effective_c × per_session_blocks / available_kv_blocks`.
   No fits. 11 unit tests.

2. **Turn-history-aware effective concurrency** in [augment_simulator_predictions_with_two_roofline.py](/root/agentic-serve/profiling/process/emitters/augment_simulator_predictions_with_two_roofline.py).
   Stateful per (profile, c) cell:
   - `K_SUSTAIN = 2` — two consecutive `pressure_active ≥ 1.0` turns ⇒
     switch from active to cohort `c` for pressure (sustained admission
     cycle, e.g. swe c=80 from turn 12+).
   - `BURST_COMPLETION_FRACTION = 0.15` — a single-turn drop in active
     sessions exceeding 15% of cohort_c ⇒ revert permanently to active
     (bulk completion, not cycling; e.g. osworld c=160 at turn 5: active
     drops 104→47).

   Both thresholds are physically motivated (cohort completion dynamics),
   not tuned. 6 unit tests covering sustained / recovering / blip / burst /
   missing-telemetry cases.

3. **Validation script** [validate_two_roofline_tpot.py](/root/agentic-serve/profiling/process/predictors/validate_two_roofline_tpot.py)
   emits per-cell APE CSV plus the verdict markdown.

4. **Dashboard wired** [ServingPredictionsPage.tsx](/root/agentic-serve/inference-benchmark/dashboard/src/components/ServingPredictionsPage.tsx)
   — fourth (solid green) line per turn for TPOT only. Tracks observed
   shape on saturating cells; drops back to T_lower on recovered cells.

## What didn't work (and why)

1. **Naive step-counter formula** (counting mixed vs decode-only steps
   each turn): under-predicted saturating cells by 5–7× because the
   amplification mechanism isn't step counting — it's per-session ITL
   burstiness under chunked-prefill admission.

2. **Sigmoid interpolation around pressure=1**: with steepness=2, gave 50%
   weight at the boundary, inflating low-pressure predictions. Replaced
   with piecewise-linear `(pressure − 1)/2`.

3. **Re-prefill term in prefill demand** (`prefill = c × new_prefill + (c −
   running) × cached`): treats completed sessions as evicted-and-cycling.
   Over-predicted recovered cells (osworld late turns, chat high-c). The
   turn-history state machine replaces this.

4. **Sustained-saturation via current-turn pressure only**: at swe c=80
   turn 28, active=36 ≈ capacity_batch=35 → pressure_active=1.03 → w≈0,
   missing the obvious saturation. Required tracking pressure across
   turns.

## Open paths forward

User noted MAPE can still improve and wants **a predictor from another
angle** to add to the current setup. Some directions worth exploring:

- **Sharpen the interpolation ramp** above pressure=1 (e.g. saturating at
  pressure=1.5 instead of 2). Closes the magnitude gap on swe/terminal
  late turns (current peak prediction ~140 ms vs observed ~250 ms). One
  parameter, but it's directly tunable to match the observed saturating
  level.

- **Per-step scheduler simulation** to predict coverage explicitly: track
  chunked-prefill admission queue, decode-batch composition per step, ITL
  burstiness for sampled sessions. Higher fidelity but vLLM-version
  brittle.

- **Bandwidth-aware T_upper** for very long contexts: today T_upper is the
  compute-bound chunked-prefill cost. For ctx > some threshold the prefill
  becomes bandwidth-bound (huge KV reads), pushing the ceiling higher.
  `T_upper = max(compute_cost, bandwidth_cost)`.

- **Bench-runner-side ITL modeling**: capture the queue-wait component
  that inflates client-side `mean(itl)` vs engine throughput. Requires
  modeling cohort arrival timing.
